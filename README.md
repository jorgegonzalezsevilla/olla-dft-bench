# olla-dft-bench

Reproducible, honest benchmarks of [Olla-DFT](https://github.com/jorgegonzalezsevilla/olla-dft)
against other open-source tools that work with Quantum ESPRESSO, on the same inputs, on the same
machine, with the same rules for everyone.

**Results:** [results/README.md](results/README.md) lists every run; each run has a `report.md`
and the raw `results.json`. Dashboard: [docs/index.html](docs/index.html) (open locally or via
GitHub Pages). Independent verdicts: [judge/verdicts](judge/verdicts); what changed because of them: [judge/RESPONSES.md](judge/RESPONSES.md).

## Reliability update (0.2.0)

New runs fail explicitly when a process, grade, expected repetition, retained artifact, or QE convergence/energy check fails. `verify` checks both completeness and successful execution. Old runs remain historical evidence: their output is labelled `LEGACY CONSISTENCY ONLY`, and cannot inherit the stricter guarantees retroactively. In particular, the audit run `20260904-143453` failed all QE launches because MPI sockets were blocked; it is not a successful end-to-end result.

The September audit and its correction record are in [review/](review/). A valid geometry grade now checks species, positions, cell metric, pseudopotentials, grid shifts, occupations, and both cutoffs. Gap grading includes VBM and CBM. HPKOT comparisons check coordinates as well as segments; other conventions are displayed separately and excluded from performance rankings.

## Why this exists

Olla-DFT is a one-person project. Its author wants to know where it is slow, heavy or wrong, not
only where it shines. So the benchmark is built to be hard to game:

- **Same input, same machine, same process model** for every tool. Each measurement is a fresh
  process, so import cost counts, as it does on the command line.
- **Correctness uses fixed tolerances and explicit references** (`tools/reference.py`).
  Structure parsing uses ASE; symmetry and HPKOT use spglib/seekpath. These shared dependencies
  limit independence and are disclosed in the protocol.
- **Every aggregate is recomputable.** `python bench.py verify results/<run>` recomputes medians,
  dispersion and grades from the raw samples, checks the SHA-256 of every input and regenerates
  the report byte for byte. If a sentence in a report disagrees with the raw data, the data wins.
- **The "areas of opportunity" section is generated by rule**, not written by hand: any cell where
  Olla-DFT is more than 1.15× slower or heavier than the best supported competitor, or mismatches
  the reference, is listed, together with a full per-cell ratio table with bootstrap intervals.
- **Coverage is stated, not hidden.** A tool that cannot do a task is marked *not supported* with
  the reason; that is information, not a failure.
- **An independent evaluator is part of the protocol.** `python bench.py judge-pack results/<run>`
  builds a packet with the protocol, the report and the results for another model or a human to
  judge ([protocol/JUDGE.md](protocol/JUDGE.md)). Verdicts are committed unedited.
- **The environment is fingerprinted and warned about**: CPU model and topology, frequency
  governor, turbo state, load average, kernel, every package version, git SHAs.

## What is compared

| task | contestants | reference |
|---|---|---|
| structure → space group, primitive cell | Olla-DFT, ASE+spglib, pymatgen | spglib directly |
| structure → high-symmetry k-path | Olla-DFT, seekpath, ASE, pymatgen | seekpath (HPKOT) |
| E(V) table → Birch–Murnaghan V0, B0 | Olla-DFT, ASE, pymatgen | analytic linear fit, no optimiser |
| pw.x output → band gap, VBM, CBM | Olla-DFT, qeschema (XML); ASE (text output); pymatgen: neither | independent XML parse / pw.x's own HOMO-LUMO line |
| structure → pw.x scf input | Olla-DFT, ASE, pymatgen | parsed back with ASE |
| end to end: each tool's input → pw.x | Olla-DFT, ASE, pymatgen | agreement of total energies |

Details, tolerances and isolation in [protocol/PROTOCOL.md](protocol/PROTOCOL.md).

## Run it yourself

```bash
git clone https://github.com/jorgegonzalezsevilla/olla-dft-bench && cd olla-dft-bench
python3 -m venv .venv && .venv/bin/pip install -r requirements.lock
python bench.py env                              # environment and warnings
python bench.py run --reps 15 --isolate          # add --with-qe if you have a working pw.x
python bench.py verify results/<run_id>
python bench.py judge-pack results/<run_id>      # packet for an independent evaluator
```

`--isolate` pins the process to the fastest core and, on Linux with systemd, runs it in a
transient scope with `MemoryMax=3G` and `CPUQuota=100%`. A `Dockerfile` pins Python packages; its base image and OS packages are not immutable. To compare **other software**, add a wrapper in `tools/` that prints one
`@@RESULT {json}` line and list it in `benchlib/tasks.py`; the grading is applied unchanged.

## Periodic runs

`systemd/` has a user timer that runs `scripts/run_periodic.sh` weekly: update Olla-DFT to the
current `main`, run, verify, build the judge packet, commit and push. Install with:

```bash
mkdir -p ~/.config/systemd/user && cp systemd/* ~/.config/systemd/user/
systemctl --user daemon-reload && systemctl --user enable --now olla-dft-bench.timer
```

A GitHub Actions workflow runs monthly on a shared runner; those results are labelled
`ci-runner` and are indicative only, because the machine is not controlled.

## Honesty statement

The benchmark was written by the author of Olla-DFT. Everything that could be biased by that is
either mechanical (grading, thresholds, environment warnings, verify) or delegated (independent
evaluator). If you find a design choice that favours Olla-DFT, open an issue: fixing the benchmark
matters more than the score.
